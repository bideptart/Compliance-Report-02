# TeleComply Compliance Suite

A full-stack compliance management platform for telecom carriers — tracking customer compliance against RMD, FCC Form 499, FRN, and Intermediate Provider Registry requirements, plus agreements, KYC documents, and trouble tickets.

## Stack

- **Frontend**: React + Vite (`src/`)
- **Backend**: Django + Django REST Framework (`backend/`)
- **Database**: SQLite (local dev)

## Project Structure

```
├── src/                # React frontend (pages, components, api clients)
├── backend/            # Django backend
│   ├── config/          # Project settings/urls
│   ├── customers/       # Customer records + compliance calculation
│   ├── rmd/              # RMD verification
│   ├── fcc499/           # FCC Form 499 verification
│   ├── intermediate_registry/  # Intermediate Provider Registry checks
│   ├── agreements/       # Customer agreements
│   ├── documents/        # Document management
│   ├── kyc/               # KYC records
│   ├── trouble_tickets/  # Trouble ticket workflow
│   └── dashboard/        # Aggregate stats/recent activity
└── public/              # Static frontend assets
```

## Getting Started

### Backend

```bash
cd backend
python -m venv venv
venv\Scripts\activate      # Windows
pip install -r requirements.txt
python manage.py migrate
python manage.py runserver
```

### Frontend

```bash
npm install
npm run dev
```

The frontend dev server runs on `http://localhost:5173` and expects the Django API on `http://localhost:8000`.

## Notes

- `backend/db.sqlite3` and `backend/media/` (uploaded documents) are intentionally excluded from version control — they contain local/real data.
- `backend/venv/` and `node_modules/` are excluded — install dependencies from `requirements.txt` / `package.json`.
- The Django `SECRET_KEY` in `backend/config/settings.py` is the default dev-only "insecure" key generated by `django-admin startproject`. Rotate it and move it to an environment variable before any real deployment.
